## Live recording

- Connect to `wss://api.elevenlabs.io/v1/speech-to-text/realtime` with the `xi-api-key` header, `model_id=scribe_v3_live`, `audio_format=pcm_16000`, and `commit_strategy=manual`. The benchmark used 16 kHz mono signed PCM in paced frames and sent an explicit commit when audio ended. [Server-side streaming](https://elevenlabs.io/docs/eleven-api/guides/how-to/speech-to-text/realtime/server-side-streaming) · [API reference](https://elevenlabs.io/docs/api-reference/speech-to-text/v-1-speech-to-text-realtime)
- Give each recording its own connection and operation ID. Keep network work off the microphone thread. A delayed connection can buffer audio in order without blocking capture. Cap the pending queue and use bounded connection and completion waits. Keep the original recording available through stop for history or an authorized retry.
- The current cloud worker waits 10 seconds before draining recorder deltas. Preserve that path for its existing callers. Scribe needs the start of the session, so use the existing capture and stop boundaries with one owner for the sample cursor. At stop, send the unsent suffix once, using the real sample boundary before upload padding. Keep buffered audio from before key-down through the final captured sample.
- The existing stop-time estimate is an upper bound. Scribe instead checks macOS keyboard state and unchanged native event counts at the plain Fn press and at a poll after 200 ms. The proof belongs to that recording and must exist by release. Ambiguous holds are discarded. Configured shortcuts other than plain Fn push-to-talk use their normal start behavior.
- Uttr verifies a fresh Fn gesture even when another ordinary key was already down. Direct paste can leave a synthetic key-down behind. Held modifier chords, pressed mouse buttons, or intervening key activity prevent verification.
- The server can auto-commit at about 36 seconds and sends no separate final event. Use acknowledged manual commits well before that limit, with one outstanding commit and buffered audio while it settles. On release, settle the in-flight commit and then commit the unsent tail. Append segments by acknowledgment order, including identical phrases spoken twice. Use the error path if coverage is uncertain. The 150 ms silence probe returned `commit_throttled` with a 300 ms minimum for uncommitted audio. Verify the smallest padding needed for a short final tail while keeping the real samples for Uttr's speech checks. Test release during a prior commit with a public long clip that ends in a distinct word. [Commit strategies](https://elevenlabs.io/docs/eleven-api/guides/how-to/speech-to-text/realtime/transcripts-and-commit-strategies) · [Event reference](https://elevenlabs.io/docs/eleven-api/guides/how-to/speech-to-text/realtime/event-reference)
- Use the same terminal speech and cancellation checks as other dictation providers. A completed empty response is no speech. Map authentication, quota, and connection errors into the existing provider error UI. Close the Scribe connection and discard any partial transcript on error. The user can switch to Groq or another model in the picker.
